The validator now has an `UNVERIFIABLE` verdict: when it finds no defect and only the environment (a browser, a service) stops it from running a criterion, it posts a comment review instead of CHANGES_REQUESTED and moves the issue to `status:blocked-on-human`, so the worker is not sent back to fix code that is not broken (#232). A host that wants such criteria run provisions the validator's worktree through the existing `worktree_setup_command` and `worktree_links`.
